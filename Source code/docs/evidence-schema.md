# Evidence schema versions 1 and 2

The archive root contains manifest.json, coverage.txt and optional collection.jsonl, raw EVTX files and normalized JSON Lines. Payload names use portable ASCII segments. SHA-256 covers the exact payload bytes and a separate SHA-256 file covers the completed ZIP.

The manifest includes schema, app_version, run, host, created, plan, attempts and payloads. A native manifest records the clock and privilege state. A retry records prior_archive. The plan includes start and end UTC, selected collectors and sources, limits and sensitive field categories. Each attempt records collector, status, count, acquisition times, privilege, reason and payload paths where applicable. Collection status is Collected, Partial, Access Denied, Unavailable, Failed or Cancelled. The newest attempt for each collector determines its current status.

Normalized records have id, kind, source, acquired, observed and fields. The id is unique within the archive. Kind is event, process, network, host, inventory, account or file. Source is a payload path. Acquired is a UTC timestamp. Observed is a UTC timestamp or null. Fields is a typed JSON object specific to the collector. Event keys include channel, event_id, event_record_id, severity, publisher PID context and rendered XML when available. Process creation time is kept separately from its acquisition time. Exact source references are archive SHA-256 plus normalized id and raw source details. Correlations use the same bundle and a bounded timestamp relationship with a process snapshot.

ZIP imports accept up to 512 members, 256 MiB per member, 512 MiB expanded, and a 1000:1 expansion ratio. JSON Lines are limited to 1 MiB each. Bundles are copied into a designated case folder using the archive digest as the copy name. SQLite migrations, annotations and derived reports are separate from the original ZIP. A duplicate import keeps the existing annotations.

Saved Windows event logs use the `archived-evtx` profile. `raw/archived.evtx` is a byte-for-byte copy of the input. `normalized/archived.jsonl` contains Windows-rendered XML and indexed event fields. The `source_evidence` manifest object stores the original filename, size, digest, detached source checksum result, readable event count, source channels and computers, and observed UTC range. The locally created wrapper has its own digest. Its verification state is distinct from the original file's checksum result. Native EVTX intake detects duplicates by the original file digest within the case. Inputs and normalized payloads are limited to 128 MiB each, and imports accept at most 100,000 events.

Schema 2 preserves original files as stored ZIP members under `attachments/`. The manifest `attachments` list references these members and stores operator-supplied provenance, optional source digest status and the indexed UTC range. The verified digest and byte count are in `payloads`. Offline disk records retain the operator's write-blocker attestation and reported read-error count. Each supplemental kind appears at most once per ZIP. Supplemental files may total up to 2 TiB, subject to local storage. The older limits still apply to ordinary collection payloads. ZIP64 directory structures and bounds are checked before opening a large ZIP. The case retains distinct custody bundles and indexes repeated supplemental bytes once per kind. Windows Traige v2.0 also reads schema 1 bundles.
